# RESUME-BUILDER FRONTEND FIX REPORT

**Date:** 2026-07-23  
**Scope:** Frontend contract update to match backend `questions` schema after CastError fix.  
**Background:** Backend fix removed `question.id` from the `questions` array. Frontend must use `question._id` or `question.tag` instead.

---

## Modified Files

### 1. `components/Resume/types/api.ts`

**Change:** Removed `id: string` from `TemplateQuestion` interface and added `_id?: string` to match the new backend contract.

```diff
 export interface TemplateQuestion {
-  id: string;
+  _id?: string;
   tag: string;
   question: string;
   type: 'text' | 'textarea';
   aiEnhanceable: boolean;
 }
```

**Why:** The backend no longer sends `id` on question objects. Mongoose now auto-generates `_id: ObjectId` for each embedded `questions` subdocument. The frontend type must reflect the actual response shape.

---

### 2. `app/dashboard/student/resume-builder/components/ResumeForm/ResumeForm.tsx`

**Change:** Replaced React list key from `question.id` to `question._id || question.tag`.

```diff
           {template.questions.map((question) => (
             <FormFieldRenderer
-              key={question.id}
+              key={question._id || question.tag}
               question={question}
               value={formData[question.tag] || ''}
               onChange={(value) => handleChange(question.tag, value)}
               error={errors[question.tag]}
             />
           ))}
```

**Why:** `question.id` no longer exists in the response. The new stable key preference is `question._id` (auto-generated by Mongoose), falling back to `question.tag` if `_id` is ever absent.
