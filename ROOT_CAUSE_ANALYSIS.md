## Executive Summary

An in-depth code-level and data-level investigation was conducted to determine why the live benchmark execution (`run_1785796639905`) produced empty field entities (`extractedEntities = {}`) and `totalFieldsCount = 0` across the comparison results, while reporting vacuous 100% F1 scores.

Three distinct root cause failure points were identified in the benchmark execution pipeline:
1. **Adapter Key Mapping Failure (Primary Cause of `totalFieldsCount = 0`):** `AdbgGroundTruthAdapter.ts` attempted to read ground truth fields from `rawGt.fields`, whereas ground truth metadata JSON files stored fields under a flattened structure or inside `extractedFields`. As a result, ground truth fields loaded as an empty object (`{}`), causing `FieldLevelEvaluator.ts` to iterate over 0 fields.
2. **Vacuous Division-by-Zero Metric Fallback:** `FieldLevelEvaluator.ts` contained fallback logic setting `precision = 1.0`, `recall = 1.0`, `f1Score = 1.0`, and `cer = 0.0` when `totalFields == 0`. This masked the missing ground truth fields by reporting a perfect 100% score for zero evaluated fields.
3. **Zero-Shot Prompt Category Omission (Cause of 0% Student ID Accuracy):** The zero-shot LLM system prompt template in `AuDicPredictionAdapter.ts` explicitly listed `CERTIFICATE` and `MARKSHEET` in its instruction category schema, but omitted `STUDENT_ID`. Consequently, the model classified 0 / 120 Student ID specimens correctly, achieving 0% accuracy for Student IDs.

## Detailed Root Cause Breakdown

### Failure Point 1: Ground Truth Field Adapter Schema Mismatch

- **Affected File:** `backend/src/benchmark/adapters/AdbgGroundTruthAdapter.ts` (Lines 49–67)
- **Code Behavior:**
  ```typescript
  if (rawGt.fields && typeof rawGt.fields === 'object') {
    for (const [key, val] of Object.entries(rawGt.fields)) {
      // ... populate extractedFields
    }
  }
  ```
- **Root Cause:** Ground truth specimen JSON files generated by ADBG store target field entities under top-level properties or inside `extracted_fields` / `candidate_fields` rather than a nested `fields` dictionary. Because `rawGt.fields` evaluated to `undefined`, `extractedFields` remained empty (`{}`).
- **Impact:** `groundTruth.extractedFields` was passed as `{}` to `FieldLevelEvaluator.evaluateSample()`.

---

### Failure Point 2: Vacuous Fallback in Field-Level Evaluator

- **Affected File:** `backend/src/benchmark/evaluators/FieldLevelEvaluator.ts` (Lines 44–85)
- **Code Behavior:**
  ```typescript
  for (const [key, expVal] of Object.entries(canonicalGt)) {
    totalFields++;
    // ...
  }
  const precision = totalFields > 0 ? matchedFields / totalFields : 1.0;
  const recall = totalFields > 0 ? matchedFields / totalFields : 1.0;
  const f1Score = precision + recall > 0 ? (2 * precision * recall) / (precision + recall) : 1.0;
  const meanCer = totalFields > 0 ? totalCerSum / totalFields : 0.0;
  ```
- **Root Cause:** When `canonicalGt` was empty (`totalFields == 0`), the loop executed 0 times. The fallback ternary operators defaulted `precision`, `recall`, and `f1Score` to `1.0` (100%) and `meanCer` to `0.0` (0%).
- **Impact:** The report generator output `overallMeanF1: 1.0` and `overallMeanCer: 0.0`, creating the false appearance of perfect key-value extraction when in reality 0 fields were evaluated.

---

### Failure Point 3: Prompt Instruction Category Schema Omission

- **Affected File:** `backend/src/benchmark/adapters/AuDicPredictionAdapter.ts`
- **Code Behavior:** The zero-shot prompt template instructed the LLM:
  > *"Classify the document as either CERTIFICATE or MARKSHEET and extract key-value fields."*
- **Root Cause:** `STUDENT_ID` was missing from the classification category enum list in the zero-shot prompt prompt instructions.
- **Impact:** For all 120 Student ID specimens, the LLM classified the document as `CERTIFICATE` or `UNKNOWN`, yielding **0 / 120 (0.00%) category classification accuracy** for Student IDs.
