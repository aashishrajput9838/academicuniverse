# RB-003.2 — Root Cause Investigation: Student Cannot See Department/Section Templates

**Date:** 2026-07-21  
**Status:** Investigation Complete — No Implementation Yet  
**Bug:** Students only see global templates; department/section templates are invisible  
**Severity:** High (breaks core feature)

---

## 1. Symptom

Faculty uploads a template with `type = "department"` and `target = "CSE"`. MongoDB confirms the document exists. Student opens Resume Builder → template list is empty (or only shows global templates). `GET /api/resume/templates` response for the student contains ONLY global templates.

---

## 2. Reproduction Steps

1. Login as faculty in `CSE` department
2. Upload template: Name = "CSE Resume", Type = "department", Target = "CSE", File = valid DOCX
3. Verify MongoDB: `ResumeTemplate` document has `type: "department"`, `target: "CSE"`
4. Login as student in `CSE` department
5. Open `/dashboard/student/resume-builder`
6. Observe: template list is empty or shows no department templates
7. Check Network tab: `GET /api/resume/templates` returns only `type: "global"` templates

---

## 3. Root Cause Analysis

### 3.1 Frontend Layer

**File:** `app/dashboard/student/resume-builder/components/ResumeBuilderPage/hooks/useTemplateSelection.ts`

```ts
const data = await fetchTemplates(backendToken);  // target NOT passed
```

**File:** `components/Resume/api/resumeApi.ts`

```ts
export async function fetchTemplates(backendToken: string, target?: string): Promise<ResumeTemplateDTO[]> {
  const url = target ? `/api/resume/templates?target=${encodeURIComponent(target)}` : '/api/resume/templates';
  return request<ResumeTemplateDTO[]>(url, { method: 'GET' }, backendToken);
}
```

The `fetchTemplates` function accepts an optional `target` parameter, but `useTemplateSelection` never passes it. The URL is always `/api/resume/templates` with no query string.

### 3.2 Backend Layer

**File:** `backend/src/controllers/resumeController.ts` — `getAvailableTemplatesController`

```ts
const targets: string[] = [];

if (req.query.target && typeof req.query.target === 'string') {
    targets.push(req.query.target);
}

query = {
    organizationId,
    $or: [
        { type: 'global' },
        { target: { $in: targets } }
    ]
};
```

When `req.query.target` is `undefined` (because frontend doesn't send it):
- `targets` = `[]`
- `{ target: { $in: [] } }` matches **nothing** in MongoDB
- Result: only `{ type: 'global' }` templates are returned
- Department and section templates are **silently excluded**

### 3.3 Data Availability Gap

**File:** `backend/src/controllers/authController.ts` — `getMeController`

```ts
const userData = {
    id: user._id.toString(),
    name: user.name,
    email: user.email,
    organization: (user.organizationId as any).name,
    organizationId: (user.organizationId as any)._id.toString(),
    role: (user.roleId as any).name,
    permissions: req.user.permissions,
    isSuperAdmin: req.user.isSuperAdmin,
    isSectionRep: !!assignedSection,
};
```

The `/api/auth/me` endpoint does **not** return `department` or `section`. The frontend `BackendUser` interface therefore has no department/section field:

```ts
interface BackendUser {
  id: string;
  name: string;
  email: string;
  organization: string;
  organizationId?: string;
  role: string;
  permissions: string[];
}
```

**File:** `backend/src/models/User.ts` — `IUser`

The User model has no `department` or `section` field.

**File:** `backend/src/models/EzoneAcademicProfile.ts` — `IEzoneAcademicProfile`

The `EzoneAcademicProfile` collection **does** have `department?: string`, but:
1. It is a separate collection, not populated in `getMeController`
2. It may not exist for all users
3. It is never queried by `getAvailableTemplatesController`

### 3.4 Cascade of Failures

```
Frontend: useTemplateSelection
  → fetchTemplates(backendToken)  // target = undefined
    → GET /api/resume/templates   // no query params
      → Backend: getAvailableTemplatesController
        → req.query.target = undefined
        → targets = []
        → query.$or = [{ type: 'global' }, { target: { $in: [] } }]
          → { target: { $in: [] } } matches NOTHING
        → Only global templates returned
          → Student sees empty list
```

## 4. Contributing Factors

| Factor | Impact |
|--------|--------|
| `fetchTemplates` supports `target` param but caller never uses it | Direct cause |
| `getMeController` doesn't expose student department/section | Frontend cannot know target |
| `getAvailableTemplatesController` relies on frontend-provided `target` | Backend doesn't auto-resolve |
| `User` model has no `department`/`section` fields | No direct source of truth |
| `EzoneAcademicProfile.department` exists but is not queried | Available data is unused |
| No integration test for department/section template visibility | Bug went undetected |

## 5. Fix Options

### Option A: Backend Auto-Resolution (Recommended)

**What:** Modify `getAvailableTemplatesController` to auto-resolve student targets from `EzoneAcademicProfile` when `req.query.target` is missing.

**Changes:**
- In `resumeController.ts`, after building `targets` from query param:
  - If student and `targets` is empty, query `EzoneAcademicProfile` for `userId = req.user.userId`
  - If `department` exists, push to `targets`
- No frontend changes required
- No student module changes required

**Pros:**
- Minimal blast radius
- Fixes bug for all students automatically
- No frontend changes needed

**Cons:**
- Additional DB query per student template list request
- Only fixes `department` type; `section` type requires additional data source
- `EzoneAcademicProfile.department` is optional; may be null for some students

### Option B: Frontend + Backend Fix

**What:** 
1. Modify `getMeController` to include `department` from `EzoneAcademicProfile` in user data
2. Update `BackendUser` interface in frontend
3. Modify `useTemplateSelection` to pass `backendUser.organization` or `backendUser.department` as `target`

**Pros:**
- Frontend has department data for other features
- Cleaner separation of concerns

**Cons:**
- Requires modifying student module (`useTemplateSelection`)
- Requires modifying auth flow (`getMeController`)
- More files changed

### Option C: Hybrid

**What:** 
1. Backend auto-resolves department from `EzoneAcademicProfile` (immediate fix)
2. Backend also exposes `department` in `/api/auth/me` (future-proofing)

**Pros:**
- Immediate fix with no frontend changes
- Long-term data availability

**Cons:**
- Still requires backend changes to two controllers

---

## 6. Recommended Approach

**Option A** for immediate fix, with consideration for **Option C** long-term.

The backend should be the source of truth for template visibility. Relying on the frontend to provide the student's department is fragile — the frontend may not have this data, or the data may be stale.

**Immediate fix (Option A):**
In `getAvailableTemplatesController`, when building the student query:
```ts
if (!isAdminOrFaculty) {
  const targets: string[] = [];
  
  if (req.query.target && typeof req.query.target === 'string') {
    targets.push(req.query.target);
  }
  
  // Auto-resolve student's department if no target provided
  if (targets.length === 0) {
    const { default: EzoneAcademicProfile } = await import('../models/EzoneAcademicProfile');
    const profile = await EzoneAcademicProfile.findOne({ 
      userId: req.user.userId, 
      organizationId 
    });
    if (profile?.department) {
      targets.push(profile.department);
    }
  }
  
  query = {
    organizationId,
    $or: [
      { type: 'global' },
      { target: { $in: targets } }
    ]
  };
}
```

**Why this is correct:**
- The backend already has `req.user.userId` and `req.user.organizationId`
- `EzoneAcademicProfile` is the canonical source for student department
- No frontend changes needed
- No student module changes needed
- Preserves existing behavior for admin/faculty

## 7. Additional Findings

### 7.1 Section-Level Templates Cannot Be Matched

There is no reliable source for a student's "section" (e.g., "CSE-A"). The `Section` model uses `representativeId` (faculty), not student membership. `EzoneAcademicProfile` has no `section` field.

**Impact:** Faculty should use `department` type instead of `section` type until a student-section mapping exists.

### 7.2 Empty `targets` Array is a Silent Failure

`{ target: { $in: [] } }` matches nothing, but the query succeeds with 200 OK. The student sees an empty list with no error message. This is confusing UX.

**Recommendation:** If `targets` is empty after auto-resolution, log a warning or return a specific message indicating no matching templates.

### 7.3 No Test Coverage

There is no test verifying that:
- A department template is visible to students in that department
- A section template is visible to students in that section
- A global template is visible to all students

**Recommendation:** Add integration tests for template visibility by role and target.
