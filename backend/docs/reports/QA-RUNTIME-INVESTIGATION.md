## STEP 5 — Save Failed Investigation

### Severity: HIGHER PRIORITY

The "Save failed" indicator is a more impactful production issue than the React warning.

### Evidence from Code Analysis

#### Frontend: `useAutoSave` hook (`useAutoSave.ts:17-31`)

```typescript
const saveDraft = useCallback(async () => {
  if (!templateId || !backendToken || isSavingRef.current) return;

  isSavingRef.current = true;
  onSaveStart();

  try {
    const response = await generateResume(backendToken, templateId, formData, 'none');
    onSaveSuccess(formData);
  } catch (error) {
    onSaveError(error instanceof Error ? error : new Error('Failed to save draft'));
  } finally {
    isSavingRef.current = false;
  }
}, [backendToken, templateId, formData, ...]);
```

**Critical finding:** `useAutoSave` calls `generateResume()` — the **resume generation endpoint** — to save drafts. This is called every 2 seconds when `formData` changes.

#### Backend Routes (`resumeRoutes.ts`)

```typescript
router.post('/generate', processResumeController);      // generates DOCX + saves draft
router.post('/generate-resume', generateResumeController); // alternative generator
router.get('/draft', getSavedResumeController);          // loads draft only
// MISSING: router.post('/draft', saveDraftController);  // does NOT exist
```

**Critical finding:** There is **no `POST /api/resume/draft` endpoint**. The only way to persist a draft is through `POST /api/resume/generate`, which executes the **full document generation pipeline**.

#### Backend Controller: `processResumeController` (`resumeController.ts:238-286`)

```typescript
export const processResumeController = async (req: any, res: Response) => {
  try {
    const { templateId, data, tone } = req.body;

    if (!templateId || !data) {
      return sendError(res, 400, 'Template ID and resume data are required.');
    }

    const template = await ResumeTemplate.findById(templateId);
    if (!template) {
      return sendError(res, 404, 'Resume template not found.');
    }

    // Full DOCX generation pipeline
    const { docxBuffer, htmlPreview } = await resumeService.processResumeTemplate(
      template.fileUrl, data, tone, enhanceableTags
    );

    // Draft save happens AFTER generation succeeds
    const studentResume = await StudentResume.findOneAndUpdate(
      { userId: req.user.userId, templateId },
      { filledData: data },
      { new: true, upsert: true }
    );

    return sendResponse(res, 200, {
      htmlPreview,
      docxBase64: docxBuffer.toString('base64'),
      studentResumeId: studentResume._id
    }, 'Resume generated successfully');

  } catch (error: any) {
    logger.error('Error generating resume:', error);
    return sendError(res, 500, error.message || 'Failed to generate resume');
  }
};
```

#### Backend Service: `ResumeService.processResumeTemplate` (`resumeService.ts:14-64`)

The generation pipeline:
1. **Fetch template from Firebase Storage** — `axios.get(templateUrl, { responseType: 'arraybuffer' })`
2. **Parse DOCX** — `new PizZip(content)`
3. **Initialize Docxtemplater** — `new Docxtemplater(zip, { paragraphLoop: true, linebreaks: true })`
4. **Set data** — `doc.setData(finalData)`
5. **Render** — `doc.render()` — **CAN THROW** if placeholders don't match data structure
6. **Generate DOCX buffer** — `doc.getZip().generate(...)`
7. **Convert to HTML** — `mammoth.convertToHtml({ buffer: docxBuffer })`

### Failure Path Analysis

The auto-save triggers this entire pipeline every 2 seconds. Any failure in steps 1–7 causes the draft save to fail:

| Failure Point | Cause | Result |
|---|---|---|
| Step 1: Firebase fetch | Network error, invalid URL, auth failure | `axios.get()` throws → caught at `resumeController.ts:282` → returns 500 |
| Step 5: `doc.render()` | Placeholder mismatch, missing data, template corruption | Throws `Error: Template processing failed` → caught → returns 500 |
| Step 7: `mammoth.convertToHtml()` | Invalid DOCX buffer after render | Warning logged but does NOT fail the request (caught at `resumeService.ts:91`) |

### What Happens on Failure

1. Backend returns **500** with message like `"Failed to generate resume"` or `"Template processing failed. Ensure template placeholders match data."`
2. `generateResume()` in `resumeApi.ts` throws because `response.ok` is false OR the JSON body doesn't have `payload.success`.
3. `useAutoSave` catches the error and calls `onSaveError`.
4. `ResumeForm` sets `draftStatus = 'error'`.
5. `DraftIndicator` renders `"Save failed"` with a red dot and optional retry button.

### Root Cause

**The "Save failed" issue is a backend architecture bug masquerading as a frontend bug.**

The root cause is the **absence of a lightweight `POST /api/resume/draft` endpoint**. Auto-save should:
1. POST `{ templateId, data }` to `/api/resume/draft`
2. Backend saves `filledData` to `StudentResume` via `findOneAndUpdate`
3. Backend returns `{ success: true, lastSavedAt }`

Instead, auto-save triggers the **full DOCX generation pipeline**, which is:
- **Expensive:** Fetches from Firebase, renders DOCX, converts to HTML — every 2 seconds.
- **Unreliable:** Any template issue, network hiccup, or placeholder mismatch fails the entire save.
- **Semantically wrong:** Draft persistence and document generation are conflated into one endpoint.

## Minimal Fix Recommendation

### Fix 1: Create lightweight draft-save endpoint (HIGH PRIORITY)

**Backend** — Add to `resumeRoutes.ts`:
```typescript
router.post('/draft', saveDraftController);
```

**Backend** — Add controller to `resumeController.ts`:
```typescript
export const saveDraftController = async (req: any, res: Response) => {
  try {
    if (!req.user) {
      return sendError(res, 401, 'Not authenticated');
    }

    const { templateId, data } = req.body;
    if (!templateId || !data) {
      return sendError(res, 400, 'Template ID and resume data are required.');
    }

    const studentResume = await StudentResume.findOneAndUpdate(
      { userId: req.user.userId, templateId },
      { filledData: data },
      { new: true, upsert: true }
    );

    return sendResponse(res, 200, {
      studentResumeId: studentResume._id,
      lastSavedAt: studentResume.updatedAt,
    }, 'Draft saved successfully');
  } catch (error: any) {
    logger.error('Error saving draft:', error);
    return sendError(res, 500, 'Failed to save draft');
  }
};
```

**Frontend** — Add `saveDraft` to `resumeApi.ts`:
```typescript
export async function saveDraft(backendToken: string, templateId: string, data: Record<string, any>): Promise<{ studentResumeId: string; lastSavedAt: string }> {
  return request<{ studentResumeId: string; lastSavedAt: string }>(
    '/api/resume/draft',
    {
      method: 'POST',
      body: JSON.stringify({ templateId, data }),
    },
    backendToken,
    false // allow empty data
  );
}
```

**Frontend** — Update `useAutoSave` to call `saveDraft` instead of `generateResume`:
```typescript
const response = await saveDraft(backendToken, templateId, formData);
```

**Impact:** Eliminates the "Save failed" issue. Auto-save becomes a lightweight DB write instead of a full DOCX generation pipeline.
