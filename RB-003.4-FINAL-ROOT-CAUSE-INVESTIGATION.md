## 2. Correct Lookup Query

```ts
const profile = await EzoneAcademicProfile.findOne({
    userId: req.user.userId,
    organizationId,
});
```

**Verification:**
- Schema field name: `userId` (confirmed)
- Other usages in codebase confirm `userId` is the correct key:
  - `backend/src/modules/ezone/repositories/ezone.repository.ts`: `EzoneAcademicProfile.findOne({ userId: toObjectId(userId), organizationId: toObjectId(organizationId) })`
  - `backend/src/controllers/dashboardController.ts`: `EzoneAcademicProfile.findOne({ userId: studentId })`
- `req.user.userId` is sourced from JWT payload (`JWTPayload.userId`), which is set to `user._id.toString()` in both `authService.ts` and `authResolver.ts`
- Mongoose auto-casts the string `req.user.userId` to `ObjectId` for the query

**Conclusion:** The lookup query is **correct**. It matches the schema and established patterns in the codebase.

---

## 3. Root Cause

The lookup is structurally correct, but it fails at runtime because **`EzoneAcademicProfile` documents do not exist for the majority of students**.

**Evidence chain:**

1. `EzoneAcademicProfile` is **only created** when a student completes the Ezone sync flow (`ezoneSyncService.verifyAndSync` → `repository.upsertProfile`)
2. There is **no seed script, migration, or automatic creation** of `EzoneAcademicProfile` for existing or new students
3. The `upsertProfile` method is called exclusively from:
   - `backend/src/modules/ezone/services/ezoneSyncService.ts:106`
   - `backend/src/modules/ezone/services/ezone.service.ts:51`
4. For students who have **never synced with Ezone**, `findOne` returns `null`
5. `profile?.department` evaluates to `undefined`
6. `targets` remains `[]`
7. MongoDB query becomes: `{ $or: [{ type: 'global' }, { target: { $in: [] } }] }`
8. `{ target: { $in: [] } }` matches **nothing**
9. Result: only global templates are returned

**Why the diagnostic logs were insufficient:**
The logs `"Resolved profile:"` and `"Resolved department:"` DO print actual values. If the profile doesn't exist, they correctly log `null` and `undefined`. The logs were not insufficient — they accurately reflected the missing data.

## 4. Minimal Code Fix

**No fix is required in `resumeController.ts`.**

The lookup query is already correct. The failure is due to **data absence**, not a code defect.

**To resolve the underlying issue, one of the following is required (outside this controller):**

1. **Create `EzoneAcademicProfile` for all students** — requires a seed script or automatic creation during user registration/onboarding
2. **Source department from an existing guaranteed data store** — the `User` model currently has no `department` field, so this would require a schema change
3. **Accept global-only templates for students without Ezone profiles** — this is the current behavior and is acceptable for MVP

